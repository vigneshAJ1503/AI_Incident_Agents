# Query language: Prometheus (PromQL)
The overview comes from these range queries (metric and label names come from configuration):
- traffic: `sum by (service) (rate(<requests>[<rate window>]))`
- error ratio: 5xx requests / all requests
- latency: `histogram_quantile(0.95 | 0.99, sum by (service, le) (rate(<histogram>_bucket[...])))`
- DB pool: active / max connections, and requests waiting for a connection
- cache: `min(<cache_up>)` (0 = unreachable)
- memory: process RSS; restarts and `OOMKilled` from kube-state-metrics

Tools: `query_range` for a breakdown the overview lacks (e.g. `histogram_quantile(0.95, sum by (endpoint, le) (rate(http_request_duration_seconds_bucket{service="..."}[2m])))`), `query` for an instant value, `get_targets` if data looks missing. Every selector must name its metric; ranges are capped by the server.
